# 媒体下载工具

一个本地运行的网页工具：**批量抓取**、**关键词搜图**、**视频下载**，三合一。
界面在浏览器里，文件全部下载到本机，不上传任何内容到第三方服务。

> 核心设计目标：**给什么网站，就抓什么网站**。
> 不写站点专用规则，全部基于「地址形态 + 字段语义 + URL 内嵌尺寸」的通用启发式，
> 因此商品站、图片站、视频站、成人站……只要是网页列表，做法都一样。

---

## 一、怎么启动

双击 **`打开工具.bat`**（推荐），会自动完成：

1. 检查 Python 与必需依赖，缺失时自动安装
2. 检查 `bin\ffmpeg.exe`，缺失时自动提取
3. 挑一个空闲端口（8848 起，被占用就自动往后找）
4. 启动服务并自动打开浏览器

> 关闭那个黑色命令行窗口 = 停止服务。

也可以用 PowerShell 启动：`.\启动工具.ps1`
（若被执行策略拦住，手动跑：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8848`，
然后浏览器打开 http://127.0.0.1:8848）

下载的文件默认保存在 **`downloads\`** 目录，按来源自动分子文件夹。

## 二、三种用法

### 1. 批量抓取（万能抓取入口）

**这是最「全能」的一个**：粘一个链接进去，就能把底下的图片、视频、流媒体全抓出来。

它有两种模式，对应两类完全不同的站点：

| 模式 | 适合什么站 | 怎么工作 |
|---|---|---|
| **列表页 / 博主页 → 逐条抓取** | 商品列表、搜索结果页（阿里 / 1688 / pixabay）、博主主页 / 频道页 | 抓这一页 → 提取详情页链接 → 下钻取原图与视频（视频页会先交给平台自带的视频列表接口） |
| **全站抓取（独立站）** | 同行公司官网、博客、作品站这类**没有统一列表页**、素材散落各页的独立站 | 用站点地图 + 同域链接把整个站走一遍，汇总全站媒体 |

> 两者的区别是「**一个列表页**」和「**一整个站**」——不是同一件事的两个选项，
> 而是两种任务：前者你已经知道内容挂在哪一页上，后者你只想「把这个站的东西都拿下来」。

两段式模式的工作方式：

```
列表页 ──① 抓媒体──► 缩略图 / 直链
   │
   └──② 提取详情页链接──► 下钻详情页 ──③ 抓媒体──► 原图 / 视频
```

列表页通常只有 300×300 的缩略图，原图和视频都在详情页里，所以第 ② 步是关键。

**视频页 / 博主页（TikTok、YouTube、B 站这类平台）走的路不一样**：
平台主页上的视频地址根本不在页面 HTML 里（前端调接口拿 JSON 再渲染），
网页抓取只会得到 0 条。所以要视频时，工具会**先把地址交给通用视频工具（yt-dlp）**，
让它用平台自带的列表接口展开成一批视频条目（含标题与封面）；
展开不了才退回网页抓取。判据只有「地址形态像人/集合页 + yt-dlp 认识这个站 + 它说这是个列表」，
不含任何站点专用规则。实测 TikTok 博主页：网页抓取 0 条 → 这条路 30 条，约 8 秒。

整站抓取的工作方式：先用 **sitemap**（`robots.txt` 里声明的 `Sitemap:` 或
`/sitemap.xml`，含 `.xml.gz`）当种子 —— 那是站点自己给出的完整页面清单；
再顺着**同域**链接广度优先遍历（跳过登录/购物车/后台/订阅源），
同页新链接按相关性排序后入队（内容页先于导航页被访问），并比对内容指纹避免重复抓同一页。

抓完会明确告诉你「本次共发现 N 个页面地址、还剩多少没抓」——
不是悄悄停在页数上限上。

> 实测（`oreelighting.com`）：只看第一页只有 15 张图 → 整站抓 20 页拿到 52 个媒体，
> 队列里还有 33 页可继续。
> 实测（`uskyled.com`）：整站抓 12 页 → 271 个媒体。
> 实测（`wordpress.org`）：从站点地图一次读到 217 个页面地址。

| 选项 | 说明 |
|---|---|
| 抓取模式 | 列表页 / 博主页 → 逐条抓取 / 全站抓取（切换后选项会自动变化） |
| 抓取页数 | 逐条模式：自动识别翻页方式（`page=` / `offset=` / `rel=next` / 路径式 `/page/2`），翻不动就停并告诉你原因。全站模式：遍历页数上限 |
| 跟随层数 | 全站模式专用：1 层（只抓首页直达）/ 2 层（推荐）/ 3 层 |
| 用站点地图当起点 | 全站模式专用：默认开启。站点没有 sitemap 时自动改为顺着链接遍历，并如实说明 |
| 详情页下钻 | **智能判断**（列表页给够了就不下钻，省时间）/ **总是下钻**（一定要高清原图）/ **不下钻** |
| 最多下钻 | 限制详情页数量，防止一次抓太多 |
| 媒体类型 | 全部 / 仅图片 / 仅视频 |
| 结果处理 | 保留全部（含缩略图）/ 只留原图 |
| 浏览器渲染 | 默认开启，**逐页自适应**：先走普通 HTTP（约 1 秒/页），只有判定为 JS 空壳的页面才上浏览器（约 10~35 秒）。所以整站模式也不需要为了速度把它关掉 |

**关于快与慢**：工具先试普通 HTTP（约 1 秒/页），发现是 JS 空壳才升级到浏览器渲染
（约 10~35 秒/页）。所以静态站很快，SPA 站慢——这是准确性的必要代价。

判断「是不是空壳」时会额外检查页面有没有 **JS 迹象**（脚本数量、前端框架挂载点）。
没有 JS 的纯静态页不会被送去渲染 —— 实测 `example.com` 这类页面因此从 49.7 秒降到 1.2 秒。

**网络层：代理与直连互为兜底**。本机若配了本地代理（`HTTP_PROXY`），它会偶发
ProxyError；工具此时会自动改走直连重试，而不是直接把这一页（以及它下面整棵详情页树）判失败。

判断「是不是空壳」时会额外检查页面有没有 **JS 迹象**（脚本数量、前端框架挂载点）。
没有 JS 的纯静态页不会被送去渲染 —— 实测 `example.com` 这类页面因此从 49.7 秒降到 1.2 秒。

**结果会自动清理三类噪音**（都是实测踩出来的）：

- **站点装饰资源**：横幅、图标、分隔条、埋点像素。
  判定靠读取 URL 里内嵌的尺寸——实测阿里结果里
  `-tps-1518-360.jpg`（4.2:1 横幅）、`-tps-297-40.png`（7.4:1 图标条）
  名字里毫无线索，只有读尺寸才认得出。
- **同一张图的多个尺寸版本**：pixabay 一类站点会把 640/1280 两个版本都放进页面，
  自动合并，只留最清晰的一份。
- **埋点与推广链接**：`hm.baidu.com/hm.gif`、带 `utm_` 的跳转链接等。

抓完会给出**抓取明细**（每页抓到多少媒体、多少个详情链接、耗时、用的是 HTTP 还是渲染），
以及**明确的警告**——比如「已用浏览器渲染但正文仍为空，站点可能返回了反爬页」，
而不是静默返回空结果。

### 2. 关键词搜图

输入关键词 → 展开「筛选项」按需设置 → 搜索 → 勾选 → 下载选中。

可用筛选：

| 筛选项 | 说明 |
|---|---|
| 清晰度 | ≥480p / 720p / 1080p / 2K / 4K，可另设上限 |
| 尺寸 | 小图 / 中图 / 大图 / 超大壁纸 |
| 长宽比 | 宽屏（横）/ 正方形 / 竖屏 |
| 类型 | 照片 / 剪贴画 / 线稿 / GIF 动图 / 透明背景 |
| 发布时间 | 24 小时内 / 一周内 / 一个月内 / 一年内 |
| 颜色 | 彩色 / 黑白 / 12 种具体颜色 |
| 人像 | 仅人脸 / 头像 |
| 授权 | 公有领域 / 可共享 / 可共享并修改 / 所有知识共享 |
| 格式 | JPG / PNG / WebP / GIF / BMP / SVG / AVIF |
| 最小体积 | ≥100KB ~ ≥3MB，过滤掉小图标和缩略图 |

**关于清晰度筛选为什么慢**：搜索接口本身不提供可靠的「原图像素尺寸」，
工具必须逐个探测原图文件头才能拿到真实分辨率。这是准确性的必要代价——
条件越严格，要探测的候选越多，耗时越长。

**结果偏少怎么办**：搜索接口在高分辨率段命中率天然偏低。
工具已按门槛自动扩大探测范围（4K 会探测全部候选），但如果仍为空，
优先放宽「清晰度」或「发布时间」，这两项影响最大。

**搜索引擎**可选 Bing / DuckDuckGo / Google，也可以组合（如三个都搜，结果合并去重）。
Google 的结果自带真实宽高与文件体积，能跳过最慢的原图探测（更快）。

Google 有两条接入通道，按顺序自动降级：**浏览器渲染**（住家 IP 可用；被判定异常
流量时可给这条通道单独配代理）→ **SearXNG 实例**（由实例服务器代抓）。两条都失败时，
搜索结果上方会逐条列出失败原因，不再只给一句「Google 不可用」。
（Google 官方 Custom Search API 已于 2026 年对新客户关闭，因此不提供 API 配置。）

同一关键词也能搜视频：点「搜视频」会切到「视频下载」页并带上关键词（见下）。

### 3. 视频下载

**两种用法**：关键词搜视频，或直接粘视频页链接解析。

> **会员视频（B 站大会员 / 优酷 / 爱奇艺）：** 这些内容的播放地址是服务端按账号
> 权限裁剪过的，非会员请求只会拿到 6 分钟左右的试看段。工具会在下载完成后核对
> 实际时长，判定为试看时自动换源重下完整版（会员 Cookie → 影视资源站 →
> 海外免费源（YouTube，可配代理）→ 解析网关，四层兜底）。也可以把大会员 Cookie
> 放进数据目录的 `vip_cookies\` 直接拿 1080P+/4K。
> 详见 `说明-Google接入与会员换源.md`。

#### 3.1 关键词搜视频（支持全网）

| 平台 | 说明 |
|---|---|
| **全网（Bing 视频）** | **默认**。走搜索引擎的视频频道，能搜到各站视频页 —— YouTube / Vimeo / Dailymotion / 各类行业站都行 |
| YouTube / Bilibili | yt-dlp 原生搜索 |

为什么要「全网」：yt-dlp 的搜索前缀只有 `ytsearch` / `bilisearch` 两个，
**原生只能搜这两家**。所以全网搜索改走搜索引擎的视频频道 ——
它索引了各站视频页，且不限站点，因此不需要为任何站点写专用规则。

搜到的结果会标出**来源站点**（如 `youtube.com`、`vimeo.com`），
点「解析」确认能下载后再点「直接下载」。

> 说明：搜索引擎会掺少量推荐内容，工具按标题与关键词的匹配度排序，
> 把明显不相关的沉到后面（只排序、不删除）。

#### 3.2 粘贴链接下载

粘贴视频页面链接 → 解析清晰度 → 选格式 → 下载。

支持上千个视频站点（由 yt-dlp 提供），包括 YouTube、Bilibili、抖音、快手、
Twitter/X、Instagram、TikTok、Twitch、Vimeo 等。

**要抓「一个主页下的所有视频」请用上面的「列表页 / 博主页 → 逐条抓取」**：
粘博主页 / 频道页 / 播放列表地址，工具会用平台自带的视频列表接口把整批视频列出来
（每条带标题与封面），勾选后由 yt-dlp 逐条下载。
单个视频页只出这一个视频 —— 那时用「解析清晰度」按档位挑更合适。

可选：
- **清晰度**：最佳画质 / 具体分辨率（解析后按实际可选项列出）/ 最小文件 / 仅音频
- **容器格式**：自动 / MP4 / MKV / WebM
- **限速**：避免占满带宽
- **字幕**：下载中文字幕与英文字幕
- **播放列表**：默认关闭；勾选后会解析整个合集并让你逐个勾选

粘贴链接时若该视频属于某合集，**默认只下这一个视频**，不会误下整个合集。

**流媒体（m3u8 / mpd）单独处理**：很多视频站用 HLS 分发，页面给出的 `.m3u8`
不是一个文件，而是一份**分片清单**——用普通方式下载只会拿到几 KB 的文本清单，
看着「下载成功」，实际打开什么都没有。工具会识别这类地址，
拉齐分片后用内置 ffmpeg 合并成可播放的 MP4：

- 主路径用 ffmpeg（`-c copy`，不转码 → 快且无损），master playlist 选流、
  AES-128 解密、时间戳修复都由它处理
- 封装三级降级：带 `aac_adtstoasc` → 不带 → 回落 `.ts` 容器，
  确保总能拿到一个能播的文件
- 没有 ffmpeg 时退化为自研分片下载（仅限未加密的 TS 流）；
  加密流会明确报错，绝不会产出一个看着像视频的坏文件

**批量抓取**结果里的「流媒体」条目会自动走这条路。

## 三、关于 ffmpeg

`bin\ffmpeg.exe` 已内置（v7.1，83MB），开箱即用。

它的作用：高清晰度视频通常是「视频流 + 音频流」分离的，需要 ffmpeg 合并。
如果 ffmpeg 缺失，工具会自动退回到「自带音轨的完整格式」，
结果是仍能下载，但可能拿不到最高画质——界面会明确提示这一点。

若被杀毒软件误删，重新提取：

```
python setup_ffmpeg.py
```

需要 `_wheel\` 目录里的安装包（已随项目保留）。

## 四、需要登录的站点怎么办

部分站点（B 站最典型，Instagram 更极端——**未登录访问直接不返回内容**）对未登录访问有风控，
会返回 412 / 403，或者干脆只给一个登录墙。这不是工具的问题——用完全默认的配置请求也会被拦。

**设置里配好的 Cookies 会用在三条链路上**（2026-09-22 起）：
网页抓取（HTTP）、浏览器渲染、以及 yt-dlp 解析/下载。
所以配好之后，「粘贴主页抓取」在需要登录的平台上也能拿到内容。

进「设置」页配置，设置页会显示**当前生效的 Cookies**（条数 + 来源文件 + 覆盖的域名），
配没配上一眼可见：

**方式一：Cookies 文件（推荐，稳定）**
1. 浏览器装一个 Cookies 导出扩展（如 Get cookies.txt LOCALLY）
2. 登录目标站点后导出为 **Netscape 格式** 的 `cookies.txt`
3. 把文件路径填进设置里的「Cookies 文件路径」
   （重新导出后最多 30 秒自动生效，不用重启）

**方式二：直接从浏览器读取**
在「或从浏览器读取 Cookies」里选 Chrome / Edge / Firefox。
> ⚠️ 需要**先完全退出该浏览器**——运行中会锁住 cookie 数据库，
> 工具会提示「Could not copy Chrome cookie database」。用方式一不用关浏览器，更稳。

> ⚠️ Cookies 等于你的账号凭据，只放在本机、不要提交到任何公共仓库。
> 工具只在本地读取并使用，不会上传。

### 平台个人主页能不能抓（实测）

| 平台 | 主页抓取 | 说明 |
|---|---|---|
| TikTok | ✅ 无需配置 | 实测 30 条 / 8 秒（走平台自带的视频列表接口） |
| YouTube | ✅ 无需配置 | 频道页会先取到分栏再下钻 |
| B 站 | ✅ 一般需 Cookies | 空间页走 yt-dlp 列表；风控严时配 Cookies |
| 微博 / Vimeo / Dailymotion | ✅ | 有公开的用户主页接口 |
| Pinterest | ⚠️ 取决于画板内容 | 画板里**有视频 pin** 就能抓到（内联数据里带 mp4）；全是图片时返回 0 并明确告知「要抓图片请到抓取图片页」。实测你的 `architecture` 画板 1246 张全是图片 |
| Instagram | ⚠️ 必须配 Cookies | 未登录访问连主页数据都不返回 |
| 抖音 / 小红书 | ⚠️ 需登录且无公开列表接口 | 网页抓取受登录墙 + 重 JS 限制，工具会如实说明 |

> 说明：上表不是「站点规则」写死的，而是「通用工具（yt-dlp / 浏览器）在这个平台能做到什么」的实测结论。

## 五、其它实用点

- **断点跳过**：同一来源地址的文件已下载过会自动跳过，不重复下载、不重复走网络。
  标记文件是 `downloads\<子目录>\.<指纹>.done`（隐藏文件，记录真实文件名）。
- **防盗链**：下载与预览都会自动带上来源页 Referer，
  前端缩略图统一走本地代理，所以图床防盗链不会导致空白图。
- **已下载**页：浏览所有已下载文件，可直接打开、保存、或在文件管理器中定位。
- **任务面板**：底部常驻，显示每个任务的实时进度、速度、成功/跳过/失败数，
  可单个取消、移除，或一键清除已完成。
- **取消是真的取消**：图片任务会立即停止提交新任务；视频任务通过进度钩子中断。

## 六、安全设计

- 服务只监听 `127.0.0.1`，不对外网开放
- **默认拒绝内网/本机地址**：抓取、代理、下载三处都做 SSRF 防护，
  避免本工具被当作内网探测跳板。确需抓取内网页面，在设置里显式开启
- 文件访问接口限定在 `downloads\` 内，拒绝路径穿越（`../`、编码绕过均已拦截）
- 代理只放行媒体类型，拒绝代理 HTML 页面；SVG 加 CSP 沙箱头，禁止内联脚本执行
- 代理有 4MB 上限，防止被超大文件拖垮
- 下载文件名做 Windows 安全化：非法字符替换、保留设备名（CON/NUL 等）加前缀、超长截断

## 九、某个站点抓不到怎么办

不用猜，一条命令拿到完整诊断：

```
python probe_site.py "https://目标站点/列表页"
```

它分三层报告，最后给出「问题在哪 + 为什么 + 下一步」：

| 层 | 看什么 |
|---|---|
| 第 0 层 静态 HTTP | 站点能否连通、是不是 JS 空壳、静态层能提取几个媒体 |
| 第 1 层 浏览器渲染 | 静态失败时，渲染能不能把内容拿出来（拿不到就说明是拦截页） |
| 第 2 层 完整抓取 | 实际抓到多少媒体、多少详情链接、各页耗时与方式 |

结论会直接说明是**哪一类**问题，例如：

- **站点不可达** → TLS / 代理 / 出口 IP 问题，不是抓取逻辑
- **疑似反爬拦截页** → 渲染后正文仍为空，需要 Cookies 或稍后重试
- **列表页无媒体但有详情链接** → 开启「详情页下钻」即可
- **抓取正常** → 并告诉你走的是静态还是渲染、合并了多少重复版本

常用参数：

| 参数 | 作用 |
|---|---|
| `--pages 3` | 连续抓 3 页，验证翻页是否可用 |
| `--drill --items 10` | 下钻 10 个详情页，验证能否拿到原图/视频 |
| `--no-render` | 只看静态层，跳过浏览器 |
| `--skip-crawl` | 只做分层诊断，不跑完整抓取（更快） |

报告同时写入 `_site_report.txt`（可读）和 `_site_report.json`（结构化）。

## 十、已知边界

诚实说明这个工具做不到的事：

1. **反爬拦截页无法绕过**：Cloudflare / Anubis 等人机验证需要真实浏览器交互，
   工具不做绕过，而是明确告诉你「已用浏览器渲染但正文仍为空」。
   实测：阿里在短时间内被反复抓取后会返回空壳页（可见文本 0 字符），
   隔一段时间再试即可，这不是工具坏了。
2. **部分站点对数据中心 IP 有风控**：需要配 Cookies（见第四节）。
3. **付费 / 会员 / 私密内容不可下载**：这是站点权限，不是工具能力问题。
4. **无限滚动站点翻不了页**：HTML 里没有分页链接时只能猜参数。工具会比对
   「翻页前后的内容指纹」，发现内容没变就停止翻页并说明原因，不会空转。
5. **直播流下载会持续增长**：直到直播结束或手动取消，文件可能非常大。
6. **搜索接口的高分辨率命中率偏低**：4K 这类严格条件下结果可能很少，属真实情况。
7. **重度交互型页面抓不全**：滚动加载、点击加载都能覆盖，但必须登录后点击
   才会出现的内容，静态渲染拿不到。
8. **浏览器渲染较慢**：约 10~35 秒/页。这是为了拿到 JS 页面真实内容的代价；
   静态站仍走 HTTP（约 1 秒/页），不会白等。

## 十一、从源码运行（开发者）

仓库里**只有源码**，不含下列可再生成的二进制（它们合计 5 GB+，由 `.gitignore` 排除）：

| 目录 | 内容 | 怎么补 |
|---|---|---|
| `browsers/` | 内置 Playwright Chromium（约 430 MB） | `set PLAYWRIGHT_BROWSERS_PATH=%CD%\browsers` 然后 `python -m playwright install chromium` |
| `bin/` | `ffmpeg.exe` 等 | 跑 `python setup_ffmpeg.py`，或放自己的 ffmpeg 进去 |
| `downloads/` `data/` `_*` | 下载产物、台账、一次性诊断产物 | 运行时自动生成 |

环境要求：**Windows 10/11 x64 + Python 3.13/3.14**。桌面窗口依赖 **Microsoft Edge WebView2 运行时**
（Win10/11 一般已自带）。

```bat
python -m pip install -r requirements.lock.txt
python launcher.py              :: 桌面窗口
python launcher.py --browser    :: 强制浏览器模式
python diag_kernel.py           :: 桌面窗口起不来先跑这个（内核判定依据全摊开）
```
